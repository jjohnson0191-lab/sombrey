# Sombrey — Product Architecture (five tabs)

The consumer app has exactly five primary destinations. Each answers one question.

| Tab | Question | Owns |
|---|---|---|
| **Home** | What is happening with me right now? | Sombrey Score (readiness), live heart rate / band state, today's vitals, activity, sleep, training, a nutrition glance, today's insight |
| **Train** | What am I doing physically? | Start a session, training plans, manual workout logging, Sombrey workouts, exercise library, workout history, workout days & reminders |
| **Progress** | How am I changing? | Vitals (full band history), readiness history, sleep, training history, weight, photos (and future strain, recovery and nutrition trends) |
| **AI** | What should I do? | Sombrey Coach, and **Nutrition** (dashboard, meal logging, food search, targets / AI Macro Calculator, meal times & reminders) |
| **Settings** | Account & controls | Account, app, privacy & data, legal, support. Developer diagnostics exist only in DEBUG builds. |

Home is a glance; depth lives in Progress. A Home card can open depth: the vitals card opens Vitals, and the nutrition card opens AI › Nutrition.

## Data provenance

The UI must always make clear which of these a value is:

1. **Device data**: measured by the band (`wearableMeasurements`, `wearableSleepSessions`, `sportPlusSessions`).
2. **Calculated Sombrey metrics**: derived by Sombrey algorithms from real data (readiness in `convex/readiness/scoring.ts`; later strain and recovery).
3. **AI interpretation**: generated by Sombrey Coach / AI plans; always labelled with `AiDisclosureBadge`.
4. **User-entered data**: sets/reps/weight, manual workouts (`source: "manual"`, `userReportedCalories` labelled "your figure"), meals, plans, goals.

## External providers: infrastructure only

| Provider | Sits behind | Status in production |
|---|---|---|
| WorkoutX (exercise data) | Sombrey's `exercises` table (`workoutx.ts` syncs into it) | Key **not configured**, so the production exercise library is **empty** |
| Edamam (food nutrition) | Server-side camera meal analysis (`ai/cameraAnalysis.ts`) | Keys not configured; no food-search integration yet |
| Gemini (vision) | Camera meal analysis | Key not configured |
| OpenAI (text) | `aiCoach/providers` (single swap point) | Key **not configured**, so Sombrey Coach **cannot answer in production** |
| Hercules (subscriptions, email) | `commerce`, `emails` | Key not configured |

Consumers never see a provider's name. Plans and workouts reference Sombrey ids only, so a provider can be replaced without touching them.

## AI Coach data contracts

Today the coach context (`ai/sombreyCoachContext.ts`) reads:
- profile and goal, and coaching mode
- this week's Sombrey workout count and the last 5 workouts by name and source (so manual logs reach it as "(manual)")
- Sport+ sessions and today's nutrition vs AI-plan targets
- meal and workout schedules, body measurements, recent sleep and vitals, and the latest readiness

Still missing before deeper Phase 4 work:

- **Training detail.** Sets, reps, load and volume per workout; manual workouts' type, duration and distance; the current training plan and its next day.
- **Nutrition detail.** Meal history beyond today; `targetsSource`, so the coach never treats the legacy default targets as the user's.
- **Trends.** 7/30-day summaries of HR, sleep, readiness and training volume.
- **Strain and Recovery**, once they exist.
- **Provenance.** A tag on every item the coach receives (device / calculated / user-entered / AI).
- **Clean-up.** Remove the legacy "coach-assigned workouts" line (from `workoutLogs`), which conflicts with Sombrey having no human coaching.
- **Training load.** Readiness's `trainingLoad` uses Sport+ session duration only, so Sombrey workouts without a band session, and manual logs, don't count yet.
